# 06｜柔性创作 Lite

## Interface

`ContentKernel + selected_evidence + target_medium + user_locks → DraftPackage`

DraftPackage 包含一份主成稿、所用证据/案例/模型指针、未解决风险和紧凑审阅回执。

## 主线

创作必须有当前最佳主观判断和清晰主线。世界复杂不要求作品平均铺开所有方向；除非主题就是复杂性本身，否则选择最能增加读者理解的一条切入面。

一条主线不等于只能有一个句子。必要的子判断、反例、限定和多阶段机制可以进入，但都要推进同一读者承诺。

## adaptive_mode

根据任务选择最小够用链：

- direct：用户已给主题、判断和材料，直接建立 ContentKernel；
- guided：主题确定，但主判断、案例岗位或结构仍需讨论；
- research-backed：承重事实或时效信息需先经过 SearchLite；
- revision：已有稿件，冻结合格部分并修最早失败层。

模式可在发现真实缺口后升级，不因后台规则多而默认走最长链。

## 装配

1. TopicBrief：读者、问题、载体和范围。
2. ContentKernel：主判断、必要关系、结论边界和用户锁定项。
3. Evidence/Case Map：每个来源、模型和案例承担什么岗位。
4. Reasoning Spine：各段如何使读者从问题走到结论。
5. Draft：默认只生成一份完整正文。
6. DeltaReview：只报告会造成读者损失的缺口。

模型和案例通过 AssetReusePlanner 柔性调用。`no_fixed_quota`：不用也成立就不调用；一个完整案例能承担任务时不拆成多个标签；多个案例能揭示关键边界时可以扩展。每个调用必须通过删除测试。

## 候选与审阅成本

- 默认不并行生成多份完整全文。
- 真正存在互斥策略时，先给差量 OptionCard；用户选择后再生成全文。
- 默认一轮审阅。只有事实、语义、结构、权利或用户锁定项出现阻断失败才追加。
- 只有 ContentKernel 或 Reasoning Spine 失败才整篇重写；段落、例子或措辞失败只修局部。

## 信息密度

降低 AI 感和提高可读性不能变成花哨装饰、碎片标签或随机口语。完整案例、问答和连续论证允许大段文字；结构服务于认知任务。

可以删：

- 重复解释；
- 没有岗位的模型；
- 不改变判断的背景；
- 仅为显得全面而存在的分支；
- 后台评分和治理术语。

不能删：

- 主张成立所需的条件；
- 案例过程和关键变量；
- 问题与答案之间的推理；
- 反例、证据身份和结论边界；
- 用户明确锁定的内容。

## 柔性预算

`soft_target` 是正常目标，不是截断线。超过目标时先减少脚手架、未选候选和重复审阅；因高风险、长材料或完整案例需要扩展时写 `expansion_receipt`。达到硬安全上限则分篇、分阶段或请用户选择范围，保持 `semantic_truncation_forbidden`。
