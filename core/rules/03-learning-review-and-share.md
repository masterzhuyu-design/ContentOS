# 03｜学习、复习与分享闭环

## 总流程

`材料 intake → 直接教学 → 拆解问答 → 迁移问答 → 学习收束 → ReviewPlan → 可选分享卡`

材料到达后不能直接考试。先让用户获得清晰解释，再用问题检查理解；问题不能把答案写在题面里。

## 材料 intake

建立 LearningSession：

- 材料名称、来源指针、权利状态；
- 本轮学习目标与范围；
- 关键对象、主张和结构初步清单；
- 用户已有理解与可能误区；
- 当前阶段 `intake_ready`。

长材料按自然意义单元分段，不按固定字数切碎。材料不完整时说明缺口，不现编缺失内容。

## 直接教学

教学至少覆盖：

- 这是什么对象；
- 它如何运作；
- 与哪些对象发生什么关系；
- 什么时候成立、什么时候失效；
- 它改变什么判断或行动。

表达应有主线和当前最佳判断。复杂不等于把所有方向平均铺开；只有能改变理解的分支才进入前台。

`AssetReusePlanner` 可以柔性召回旧模型或案例。先看摘要，再做净增益与删除测试：不用它是否会明显降低解释力、辨析力或迁移质量。结果可以是 `use / backstage / no_use`，不设调用数量配额。

## 拆解问答

拆解问答直接测试知识对象，不问“作者怎么说”。题目可按诊断需要覆盖：

- 定义与对象边界；
- 机制链；
- 因果与相关；
- 关键关系；
- 反例和失效条件；
- 与相邻概念的区别；
- 对原判断的批评。

题量由知识结构和错误信号决定，`no_fixed_quota`。一题能暴露多个承重关系时不必拆成机械小题；多个独立误区也不能被一个宽泛问题掩盖。每个答案紧邻问题，记录用户独立完成、提示后完成或仍未闭合。

旧模型/案例可以用于对照，但不能替代当前材料的理解检查。

## 迁移问答

迁移题提供新的对象、信息或约束，让用户：

- 判断旧机制是否仍适用；
- 找出相同点和关键差异；
- 在新证据出现后更新结论；
- 选择行动并说明代价；
- 识别不能迁移的部分。

`AssetReusePlanner` 可以提供旧案例候选，但必须检查机制同构、情境差异和边界。不得因表面相似硬套；旧案例可以被判为 `no_use`。迁移支架可渐进淡出，不能把推理路线预先泄漏。

## 学习收束

生成 LearningResult：

- 当前掌握的主判断与机制；
- 拆解问答和迁移问答的真实表现；
- 仍不稳定的边界；
- 概念、模型、案例和本体关系候选；
- 下一次 ReviewPlan；
- 是否存在可选分享卡。

学习结果、资产候选和分享价值都不自动开启 CreationTrack。

## 柔性复习计划

D+1、D+7、D+30 是常用起点，不是固定日历。ReviewPlan 根据以下信号调整：

- 提取失败：缩短间隔，优先无提示复述；
- 机制混淆：安排关系辨析；
- 迁移失败：安排新情境而非重复原题；
- 高重要性或高风险：增加一次较早复核；
- 稳定掌握：延长间隔，减少重复；
- 新证据改变结论：立即创建更新复习。

每次复习记录计划时间、实际时间、任务类型、证据、结果和下一间隔。逾期不等于失败，重新排程即可。

## 普通分享卡

分享卡默认是正文型 `detached_share_export`，推荐保持：

1. 前置解读或读者问题；
2. 关键拆解问答；
3. 完整迁移案例与迁移问答；
4. 总结和适用边界。

结构可以因材料调整，但不能把问答改成碎片标签，也不能省掉输入条件和推理。只有用户明确要求图文或视频，才进入相应升级模块；只有用户明确启动创作，才进入 CreationTrack。

分享卡从 LearningResult 派生时，LearningResult 的来源摘要、问题—回答配对、完整迁移案例、边界和用户已确认内容构成 canonical source。后续讨论只形成差量：已确认调整可以应用，候选方案、被否决方案和仅用于澄清的说法不能自动进入正文。没有明确删除授权时，派生稿不能因为讨论中出现了另一种路线而遗失原承重内容。
