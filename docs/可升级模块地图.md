# 可升级模块地图

模块状态有四类：

- `CORE`：v0.1.1 默认能力，不能因为精简而删除；
- `OPTIONAL`：有真实需求和验收条件时安装；
- `GATED`：除技术条件外还需要用户明确授权；
- `DEFERRED`：当前没有成本收益证据，继续延期。

机器可读状态见 `core/upgrades/module-registry.json`。

## CORE

| Module | 作用 | 默认实现 |
|---|---|---|
| LearningLoop | intake、教学、拆解问答、迁移问答、学习收束 | Markdown/JSON |
| ReviewPlanner | 柔性 D+1/D+7/D+30 与表现驱动调整 | ReviewPlan |
| ModelCaseCapture | 模型、案例、概念、结构和技巧收录 | ReusableAsset |
| FileOntology | 对象与关系的来源绑定表达 | OntologyStatement |
| AssetReusePlanner | 旧资产摘要召回、净增益判断、按需读正文 | 文件索引 |
| ShareCardBody | 学习问答和迁移案例的正文分享卡 | detached export |
| SearchLite | 风险与证据缺口驱动的柔性搜索 | 两种来源 Adapter |
| CreationLite | 单内核、单正文、差量返工 | ContentKernel |
| QualityGate | 把可观察成品事实编译为 pass、定向修复、返回上游或阻断 | QualityObservation → QualityDecision |
| ProblemRegressionSuite | 用历史真实失败模式验证公开质量门 | 行为级回归 |

### QualityGate 与 ProblemRegressionSuite

QualityGate 是纯只读 Module。相关 TaskKind 通过 startup 获得 gate 列表，调用方把成品上的可观察事实交给同一个 Interface。它负责：

- 教学先于测试；
- 迁移题不泄露答案路线；
- 旧模型和案例得到 `use / backstage / no_use`；
- 分享卡保留完整问答、案例和推理；
- 容量溢出时不做语义截断；
- 创作主线、定向返工和 AI 感多信号判断；
- 搜索主张校准、版权局部阻断和适应性复习；
- `discussion_delta_integrity`：分享卡和创作只应用已确认讨论差量，不遗失原承重内容；
- LearningTrack 不自动进入 CreationTrack。

ProblemRegressionSuite 只通过 QualityGate 的公开 Interface 验证行为，不检查内部函数或靠关键词冒充行为测试。新增历史问题时，先写可复现场景，再扩展 Module。

两者都不获得写入、创作、发布、删除、账号、自动任务或整篇重写权限。QualityDecision 只是本轮质量裁决；真正修改仍由原 TaskKind 在现有权限内执行。

## OPTIONAL

### VisualShareAdapter

把已通过的分享卡正文生成图文。升级前需要：

- 持续存在明确图文需求；
- 正文先行；
- 权利、信息完整性、可读性和成品验证；
- 不用提示词替代实际交付。

### PlatformAnalyticsAdapter

读取真实发布数据并形成内容假设回执。升级前需要真实账号、稳定数据入口和因果边界；不能把投流与自然效果混为一谈。

### MultiFolderWorkbench

把多个相关项目根组成受控工作簇。只有出现两个以上长期相关目录时升级；个人知识系统仍是知识入口，不做全盘统一入口。

### SemanticIndexAdapter

当文件索引出现可测的召回或延迟瓶颈时，可接入语义索引。索引必须可重建，不能成为真相源。

### KnowledgeOSAdapter

可连接独立安装、只读、窄 Interface 的 KnowledgeOS。默认包不包含它，也不能因为 Adapter 存在就自动安装、刷新或调用。

## GATED

### AutomationScheduler

需要任务、频率、写入范围、停止条件和异常处理的逐项授权。不能默认启用。

### PublishingAdapter

需要平台、账号、目标成品和本次发布的明确授权；发布、删除、评论、私信、投流分别授权。

## DEFERRED

### GraphRAG / Ontology Graph

只有文件型本体出现真实关系导航瓶颈，并且迁移收益超过索引、维护和上下文成本时才考虑。需要：

- 真实 workload 基线；
- source truth 与图投影分离；
- 可重建迁移；
- 权限与删除语义；
- 质量和 Token A/B。

在这些条件前继续延期。

## 升级通用门

任何升级 Module 都必须回答：

1. 解决了什么已观察问题；
2. 为什么 Core 现有 Interface 不够；
3. 新增依赖和长期维护成本；
4. source truth 在哪里；
5. 失败和卸载后如何恢复；
6. 对 Token、质量、隐私和权限的影响；
7. 用什么真实 workload 验证；
8. 是否需要用户新的授权。

没有这些证据，只记录候选，不安装。

QualityGate 的升级还必须满足：

1. 新 gate 对应已经观察到的可复现读者损失或权限失败；
2. 输入只能是可观察事实，不把完整材料和工具原始输出塞进门；
3. 决策必须返回最早失败层和可继续路线；
4. 不把单一风格信号、分数或字数升级成硬失败；
5. 不因新增 gate 获得写入、整篇重写、发布或账号权限；
6. 必须先有行为级回归，再修改实现；
7. 现有通过场景必须继续通过，不能靠扩大阻断范围让测试变绿。
