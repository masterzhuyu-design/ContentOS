# 可升级模块地图

机器可读状态见 `core/upgrades/module-registry.json`。模块只有一个公共 owner；`full` 和 `lite` 只是启用范围不同。

## CORE

| 模块 | 作用 | 主要对象或接口 |
|---|---|---|
| CanonicalTaskContract | 28 个 TaskKind、输入、规则、预算和质量门 | task-profiles.json |
| StartupAndRecovery | 输入闭合、最小 hydration、checkpoint 恢复 | startup envelope |
| LearningLoop | intake、教学、首轮、旧知识改进、迁移、收束 | LearningSession / LearningResult |
| ReviewPlanner | 表现驱动的复习安排 | ReviewPlan |
| KnowledgeAssets | 模型、案例、概念、技巧与来源 | ReusableAsset |
| FileOntology | 文件型对象关系 | OntologyStatement |
| AssetReusePlanner | 摘要召回、净增益判断、正文按需读 | use / backstage / no_use |
| EvidenceResearch | 主张、来源、竞争解释和停止条件 | SourceCapsule |
| ContentCreation | 主题、内核、单正文和差量返工 | ContentKernel |
| QualityGate | 把可观察事实编译成裁决 | QualityObservation → QualityDecision |
| ProblemRegressionSuite | 重放历史真实失败模式 | 行为级回归 |

## PUBLIC ADAPTER

以下能力在公开合同中完整存在，但外部副作用由实例适配器实现：

| 适配器 | 对应能力 |
|---|---|
| authorized_collector | 授权范围内的信息收集 |
| platform_source_recovery | 平台来源恢复 |
| legacy_learning_import | 旧学习记录迁移 |
| empirical_runner | 冻结实验执行 |
| file_registry_single_writer | 学习 Registry 投影 |
| local_visual_renderer | 本地图文渲染 |
| account_snapshot_readonly | 账号发布后复盘 |

用户作答后的旧模型、案例和知识查询由 CORE 文件索引负责，不能因为 KnowledgeOS 未安装而跳过。KnowledgeOS 仅是可替换的只读加速器。

适配器必须声明版本、支持任务、读写范围、授权、失败副作用、幂等策略、输出 Schema 和 readback。没有适配器时任务应明确阻断，不能被静默遗忘，也不能假装已经执行。

## GATED

- 自动调度：需要任务、频率、写入范围、停止条件和异常处理的逐项授权；
- 平台发布：账号、目标成品和本次动作分别授权；发布、删除、评论、私信和投流不是同一权限；
- 真实实验：冻结方案、runner、资源和单次执行授权全部闭合后才能运行。

## DEFERRED

GraphRAG、独立图数据库或常驻向量服务只有在文件索引出现可测瓶颈、迁移收益高于维护成本时才进入。索引必须可重建，不能成为新真相源。

## 升级门

升级前回答：观察到什么问题、现有接口为什么不够、source truth 在哪里、会增加什么依赖和长期维护、失败后怎么恢复、对质量/上下文/隐私/权限有什么影响、用什么真实 workload 验证。

同一个缺陷反复出现时，应修改真实 owner 并同步测试和迁移；不要为每次事故再造 helper、receipt、registry 或第二套规则。升级成功的一个重要指标是净复杂度没有无意义上升。
