# 功能与操作流程

本文说明 ContentOS Lite 能做什么、用户平时如何操作，以及每一步会产生什么对象。

## 一、第一次安装

在发行目录运行：

```powershell
.\scripts\init-contentos-lite.ps1 -Destination '.\my-knowledge-system'
```

初始化只复制规则、脚本、模板和空 vault，不联网、不安装模型、不登录账号、不创建线程、不发布。

新工作区主要结构：

```text
AGENTS.md
.contentos/config.json
core/
scripts/
templates/
vault/
  00_Inbox/
  01_Knowledge/
  02_Learning/
  03_Creation/
  04_Projects/
  05_Assets/
  06_Reviews/
  99_Archive/
```

## 二、每次任务的统一启动

1. 判断本轮 TaskKind；
2. 准备该 TaskKind 的必需输入；
3. 运行 `resolve-startup-lite.ps1`；
4. 返回 `ready` 才执行；
5. 任务结束写目标对象和 checkpoint。

示例：

```powershell
$inputs = @{
  question = '需要核验的问题'
  freshness = 'current'
  risk_class = 'standard'
  scope = '本轮范围'
} | ConvertTo-Json -Compress

.\scripts\resolve-startup-lite.ps1 `
  -TaskKind web_search_lite `
  -InputsJson $inputs `
  -Pretty
```

缺输入时返回 `blocked_missing_inputs`，不会让执行者自由猜测。

## 三、完整学习流程

### 1. 材料 intake

用户提供书、课、文章、自己的笔记或其他材料。系统建立 `LearningSession`，记录材料指针、学习目标、范围和当前阶段。

### 2. 直接教学

先解释对象、机制、关系、边界和实际意义。必要时通过 AssetReusePlanner 柔性调用旧模型/案例；先看摘要，只有真实提高理解才读取正文。

### 3. 拆解问答

用问题检查用户是否理解知识对象本身。问题可以测试定义、机制、关系、边界、反例和批评；不机械规定题量，也不在题面泄漏答案。

每个回答记录：

- independent：独立完成；
- prompted：提示后完成；
- unresolved：仍未闭合。

### 4. 迁移问答

换一个新情境，要求用户判断哪些机制仍成立、哪些条件变化、是否应更新结论以及如何行动。旧模型/案例可以作为对照，但必须检查关键差异，不能硬套。

### 5. 学习收束

形成 `LearningResult`，记录：

- 当前掌握；
- 拆解和迁移表现；
- 未稳定边界；
- 模型、案例、概念和本体候选；
- ReviewPlan；
- 可选分享卡。

学习完成不会自动进入创作。

## 四、复习计划

ReviewPlanner 通常从 D+1、D+7、D+30 起步，但会根据真实表现调整：

- 提取失败：缩短间隔；
- 机制混淆：安排关系辨析；
- 迁移失败：安排新案例；
- 高重要性：增加早期复核；
- 稳定掌握：延长间隔；
- 新证据改变结论：立即安排更新复习。

逾期时重新排程，不把日历执行当成学习能力评分。

## 五、模型、案例和本体收录

### 模型

记录问题、输入、机制、输出、适用条件、失效条件、误用风险、案例和反例。

### 案例

记录事实背景、发生过程、关键变量、结果、解释、来源和与目标情境的差异。事实与解释分开。

### 本体

以 `subject-predicate-object` 记录对象关系，并附带范围、时间、来源、置信状态和反证。例如：

```text
沉默的证据 --constrains--> 只依据成功样本的判断
```

v0.1 使用 JSON 和文件索引，不需要图数据库。

## 六、收录资产的后期复用

AssetReusePlanner 的操作顺序：

1. 根据当前任务的对象、机制、关系和边界查询索引摘要；
2. 返回少量候选；
3. 对每项做净增益、冲突和删除测试；
4. 标记 `use / backstage / no_use`；
5. 只加载 `use` 对象正文。

它可以在教学、拆解问答、迁移问答、复习、搜索和创作中调用。没有固定调用数量，0 个合适候选优于硬塞模型。

## 七、普通分享卡

用户说“做成分享卡”时，默认只生成正文：

1. 前置解读；
2. 拆解问答；
3. 完整迁移案例与迁移问答；
4. 总结与边界。

结构可以适配材料，但不能把问答和案例压成碎片。图文、视频和平台发布属于独立升级模块或显式任务。

## 八、柔性搜索

SearchLite 先选择 quick、standard 或 deep 中最小够用模式。

- 已有权威来源的窄事实可以很快停止；
- 多来源主张、争议或时效问题按证据缺口扩展；
- 高风险问题提高来源和核验强度；
- 领域来源集中时不强造多样性；
- 原网页正文不进入主上下文，只保留 SourceCapsule 和精确指针。

数字是起点与预算软线。扩展时说明理由和停止条件。

## 九、柔性创作

CreationLite 的默认链：

```text
TopicBrief
→ ContentKernel
→ Evidence/Case Map
→ Reasoning Spine
→ 一份正文
→ DeltaReview
```

它保留主观判断、完整案例和连续论证。模型、案例和结构按岗位调用，不凑数量。默认不生成多份完整候选；真正存在互斥路线时先展示差量，用户选择后再成稿。

审阅只修最早失败层。只有内容内核或主论证骨架失败才整篇重写。

## 十、恢复与 checkpoint

任务中断后只从 checkpoint 恢复：

- 当前阶段；
- 最近已核验事实；
- 证据指针；
- 用户锁定项与权限；
- pending；
- 下一轮必读。

不要从完整旧会话恢复，也不要把失败稿当真源。

## 十一、质量门操作

相关 TaskKind 在 startup 的 `generator_view.quality_gate_interface` 中返回本轮应执行的 gates。质量门是只读判断，不生成正文、不写 vault、不发布，也不自动整篇重写。

标准顺序：

1. 从 canonical source、当前任务和已确认用户要求生成一份候选；
2. 把成品上可观察的事实写成 `QualityObservation`；
3. 调用 `evaluate-quality-gate-lite.ps1`；
4. 根据 `QualityDecision` 处理：
   - `pass`：可以继续交付；
   - `targeted_repair`：冻结已通过内容，只修命名缺口；
   - `return_upstream`：返回教学、ContentKernel 或 Reasoning Spine 等最早责任层；
   - `blocked`：先补真源、权限、观察或范围选择。
5. 只有仍存在阻断失败时才追加一轮，不反复重写整篇。

示例：

```powershell
$observation = @{
  schema = 'contentos-lite-quality-observation-v1'
  observation_id = 'share-discussion-check-001'
  gate = 'discussion_delta_integrity'
  task_kind = 'share_card_lite'
  facts = @{
    canonical_source_bound = $true
    canonical_load_bearing_unit_count = 8
    preserved_load_bearing_unit_count = 8
    confirmed_adjustment_ids = @('ADJ-TITLE')
    applied_adjustment_ids = @('ADJ-TITLE')
    candidate_option_ids = @('OPTION-REMOVE-QUESTION')
    rejected_option_ids = @()
    clarification_only_ids = @()
    explicit_deletion_authorized = $false
  }
} | ConvertTo-Json -Compress -Depth 8

.\scripts\evaluate-quality-gate-lite.ps1 `
  -ObservationJson $observation `
  -Pretty
```

### 讨论后继续创作或生成分享卡

讨论开始前冻结：

- `canonical_source_digest`；
- `load_bearing_units`；
- 分享卡的问题—回答配对、迁移案例和边界；
- 创作的 ContentKernel、Reasoning Spine 和用户锁定项。

讨论内容分为：

- `confirmed_adjustment`：用户已确认，允许进入派生稿；
- `candidate_option`：仍在比较，不得自动采用；
- `rejected_option`：已经否决，不得回流；
- `clarification_only`：只用于理解问题，不等于修改原内容。

新稿的 applied adjustments 必须是 confirmed adjustments 的子集。质量门返回 `apply_confirmed_deltas_only` 时，只应用确认差量；返回 `restore_load_bearing_units` 时，从 canonical source 恢复遗漏内容，不能根据最近对话重新猜。

这一流程同时适用于：

- `share_card_lite`；
- `content_creation_lite`；
- `content_review_lite`。

观察字段缺失时质量门返回 `blocked / observation_closure`，不会把“没有证据”误判为通过。
