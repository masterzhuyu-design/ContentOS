# 功能与操作流程

这份文档说明公开版 ContentOS 从接到任务到留下资产的完整工作方式。想先看口语版，请读 `docs/对外聊天简要说明.md`。

## 一、系统只有一个公共内核

`core/profiles/task-profiles.json` 是 28 个 TaskKind 的 canonical 合同。`full` 开放全部合同；`lite` 只是其中 15 项的 allowlist。两者共用规则、Schema、质量门和用户数据。

公共仓库定义任务目的、必需输入、来源权限、规则 hydration、预算、质量决策映射和停止状态。私人实例提供笔记、学习历史、checkpoint、账号和外部工具。平台或账号行为通过适配器接入，不能反过来改写任务合同；适配器自报授权也不能让公共解析器直接放行。

## 二、每一轮都走同一条主干

```text
真实目标
→ 选择 TaskKind
→ 用当前 turn 或已核验文件闭合必需输入
→ canonical startup
→ 执行当前任务
→ 只读质量判断
→ 经授权写入资产或 checkpoint
→ 回读可观察结果
```

启动示例：

```powershell
$turn = 'your-host-current-turn-id'
$input = @{
  schema = 'contentos-task-execution-input-v1'
  scope_id = 'research-example'
  current_turn_id = $turn
  task_kind = 'public_information_research'
  task_stage = 'evidence_research'
  bindings = @(
    @{role='question'; adapter='current_turn_inline'; source_pointer="current_turn:${turn}:question"; value='这个判断是否成立'},
    @{role='freshness'; adapter='current_turn_inline'; source_pointer="current_turn:${turn}:freshness"; value='current'},
    @{role='risk_class'; adapter='current_turn_inline'; source_pointer="current_turn:${turn}:risk_class"; value='standard'},
    @{role='scope'; adapter='current_turn_inline'; source_pointer="current_turn:${turn}:scope"; value='只研究公开信息'}
  )
} | ConvertTo-Json -Compress -Depth 8

.\scripts\resolve-contentos-startup.ps1 `
  -Profile full `
  -TaskKind public_information_research `
  -TaskExecutionInputJson $input `
  -Pretty
```

只有 `status=ready` 且 `generation_allowed=true` 才继续。缺输入会得到 `blocked_missing_inputs`；错误 turn、文件不存在或摘要变化也会阻断；lite 不包含的任务会得到 `blocked_profile_scope`；规则包越过硬预算会阻断，而不是删掉承重信息。旧 `InputsJson` 不能再用“看起来像真的字符串”绕过这些门。

## 三、学习闭环

学习不是“总结完就结束”，而是连续的五段：

1. `fixed_learning_intake` 或 `public_learning_intake` 绑定材料、目标和来源；
2. `fixed_learning_teaching` 先讲对象、机制、关系、边界和实际意义；
3. `fixed_learning_first_round` 必须同时绑定当前学习记录和本轮完整用户作答，在不泄露答案的情况下检查独立理解；折叠界面不能被当成“用户只答了一题”；
4. 用户作答后，`fixed_learning_old_knowledge_query` 直接查询随实例保存的文件索引；KnowledgeOS 只能作为可选只读加速器。只有存在可观察净增益时才用于改进答案；
5. `fixed_learning_transfer_round` 重新绑定当前学习记录、本轮作答、迁移情境和已有 probe 历史，换情境检查迁移，并产出学习结果、复习计划和资产候选。

迁移题不是“换个名词再问一遍”。系统会比较它与用户刚完成的回答路线：路线等价且没有新增承重推断时，默认停止或重写；只有用户明确要求重复练习，或最近确有错误需要定向补救时才继续，而且这两种结果不会冒充新的迁移能力证据。

旧知识查询是“可达但不常驻”：每次有需要都能调用，但不把整个资产库塞进上下文，也不能因为适配器未安装就假装查询过。

复习从 D+1、D+7、D+30 等候选间隔起步，但根据提取失败、机制混淆、迁移失败、重要性和稳定掌握动态调整。逾期只重新排程，不把日历执行当能力评分。

## 四、知识资产如何留下

- `model_library_maintenance` 维护模型、案例、概念、技巧和其来源、适用条件、失效条件；
- `link_maintenance` 只建立真实存在、语义明确的关系；
- `knowledge_query` 从文件型真相源读取，并返回精确证据指针；
- `learning_registry_sync` 通过单写者适配器把已完成回执投影进 Registry；Registry 不是学习正文的替代品。

资产先以摘要和索引可达，正文按需读取。候选会做 `use / backstage / no_use` 判断，避免“既然收录了就必须塞进每次回答”。

## 五、研究和判断

- `public_information_research` 从问题、时效、风险和范围出发，建立主张、来源和竞争解释；
- `restricted_information_collection` 只在明确授权范围内通过收集适配器工作；
- `platform_video_recovery` 用来源恢复适配器处理平台视频或缺失证据，不能把推测当原文；
- `non_ergodic_decision_review` 先看不可逆损失、可逆探针和退出条件，不用平均情境掩盖极端风险；
- `empirical_research_preregistration` 在观察前冻结问题、干预、对照、指标和停止规则；
- `empirical_research_execution` 只通过显式 runner 和授权执行冻结方案。

搜索扩展由证据缺口驱动。窄事实有权威来源即可停止；争议、时效或高风险问题才增加核验强度。来源数量本身不是质量。

## 六、创作和分享

创作链通常是：

```text
application_discovery（可选）
→ direct_topic_creation
→ ContentKernel
→ content_creation
→ content_review
→ share_card_body 或其他明确交付
```

内部会检查事实、逻辑、受众、主线和旧资产，但对外成品不自动变成审计报告。人物、历史或虚构世界按具体时代、社会、物种、寿命、权力和因果逻辑写，不强塞现代人类模板。

讨论中的内容分为已确认修改、候选方案、已拒绝方案和仅用于理解的说明。新稿只能应用已经确认的差量。审阅定位最早失效层，局部问题局部修；只有内容内核或主论证确实失败才整篇重写。

`share_card_body` 只生成 detached 正文。`share_visual_local` 需要已批准正文、视觉 brief、渲染适配器和授权。任何平台发布另行授权。

## 七、独立审阅、维护和恢复

- `artifact_semantic_review` 只根据冻结目标、来源边界和当前产物做独立语义判断，不取得修改权；
- `architecture_maintenance` 回到真实 owner 合并重复、修改冲突、删除失效内容，并检查净复杂度是否下降；
- `learning_method_correction` 修复可复现的学习流程缺陷，同时保留已有学习状态；
- `thread_recovery` 只从 checkpoint、回执和稳定指针恢复，不重放完整旧会话；
- `learning_transfer_history_backfill` 通过显式迁移适配器导入旧记录，旧数据保持可回读。

checkpoint 必须是工作区内真实存在、摘要匹配且结构可恢复的文件。外部 AI 客户端不能用自己的会话 ID 选中 checkpoint；它们每个阶段都重新绑定宿主当前 turn，并只得到 proposal-only 视图。暂停、续接或宿主原生重试后同样重新核对，不复用旧阶段摘要。

## 八、质量门

`scripts/evaluate-contentos-quality-gate.ps1` 接收可观察事实，不生成正文、不写 vault，也不发布。输入和输出分别是 `contentos-quality-observation-v1` 与 `contentos-quality-decision-v1`。

```powershell
$observation = @{
  schema = 'contentos-quality-observation-v1'
  observation_id = 'research-001'
  gate = 'search_claim_calibration'
  task_kind = 'public_information_research'
  facts = @{
    claim_strength = 'qualified'
    evidence_strength = 'strong'
    source_count = 2
    independent_source_count = 2
    primary_source_count = 1
    primary_source_available = $true
    primary_source_used = $true
    single_source_conclusion = $false
    adjacent_source_evidence = $false
    direct_source_evidence = $true
  }
} | ConvertTo-Json -Compress -Depth 8

.\scripts\evaluate-contentos-quality-gate.ps1 `
  -ObservationJson $observation `
  -Pretty
```

质量门返回 pass、定向修复、返回上游或阻断，并指出最早失败层。测试数量、回执数量或长篇分析都不能替代真实修改与行为回读。

## 九、验证公开版

```powershell
.\tests\run-all.ps1
```

验证包括：canonical 合同、28 项合同覆盖、full/lite 准入、28 个历史问题场景、输入与规则预算、路径穿透、启动性能、私人状态排除、发布清单，以及 full/lite 两种干净安装、vault Git 隔离和二次初始化整实例不变。

合同覆盖不表示私人数据被公开，也不表示模型已经产出高质量结果，或未安装的账号、平台、实验、渲染适配器已经产生真实效果。
